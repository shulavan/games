# 江戸川区イベント iCal v3.2.13

## v3.2.13 の変更点

- 区公式CSVの詳細URL取得上限を300件から1,000件に拡大し、CSV行の後半にある詳細ページも取得できるよう改善。詳細ページに複数の開催日時が箇条書きで掲載されている場合、各日程・各時刻を個別VEVENTにする。
- 「えどがわ朝日創業塾」は朝日信用金庫の公開日程から江戸川会場の日付だけを抽出し、隔週金曜日の実開催日・18:30～20:30を日別登録。台東会場の日程は除外し、CSVの連続期間イベントは専用日程で置き換える。専用ページの取得に失敗した場合もCSVの期間値を誤った日別予定として出力せず、ステータスに警告を残す。
- 同日・同時刻・同会場で、短い公式タイトルが長いまいぷれタイトルに含まれる場合も重複統合。例:「第12回 新川みどりとごちそう市」と「第12回新川みどりとごちそう市＆ミニミニ動物園」。公式側のタイトル・時刻・会場を維持し、公式画像がない場合はまいぷれのイベント画像を引き継ぐ。
- 同日・同一タイトルの重複は、URLやドメイン、会場表記が異なっても照合。区公式イベントの時刻・会場・住所・座標を優先し、参照元URLは両方保持。
- まいぷれ詳細本文はイベント見出しから抽出し、「開催予定のイベントが中止・延期…」等の共通注意書きと、「地図で場所を確認する」「シェア」「掲載ご希望の方はこちら」以降のフッターを除外。
- CSVに詳細URLがある場合は詳細HTMLも確認し、本文に記載された開催日・時刻をCSVの期間値より優先。
- 詳細ページで実際の開催日が確認できないCSVの単なる開始日・終了日は、日別イベントへ機械展開しない。特に落語会・寄席の複数日CSV期間は、公演日程を確認できない場合は出力を保留。
- HTML詳細に個別開催日や定期開催日が明記されている場合は、日ごとの独立VEVENTとして保持。日ごとに時刻が異なる場合も、各日程を別イベントとして扱う。
- 鶴岡市のイベント名に「観光物産展」を明記。
- Kintone/KViewerは引き続き調査・収集対象外。今回の修正では再導入していない。
- ローカル回帰テスト158件すべて成功。GitHub Actionsでの実データ収集確認は別途必要。

### 開催日を1日ごとに分割

- HTML詳細等で実際の開催期間・開館日と確認できた複数日開催は、開催日ごとに独立した VEVENT を生成します。休館日が明記されていれば除外します。
- 毎週・毎月第N曜日の開催や、個別の日付が明記された複数回講座は、各開催日を個別の VEVENT に展開します。
- CSVの開始日・終了日だけでは毎日開催と判断しません。詳細ページで開催日を確認できないCSV期間は、日別に水増しせず期間イベントとして保持します。
- 複数日・定期開催イベントは `PRIORITY:9`（iCalendarで最低優先度）を設定し、通常の単発イベントより目立ちにくくします。表示順への反映はカレンダーアプリの仕様に依存します。
- 開催日ごとのUIDを生成するため、同じイベントでも開催日が違えば別レコードとして扱います。

### 定休日・休館日

- 「月曜日は休館日」「定休日は月曜日」など、曜日が明記されている場合は該当曜日を除外します。
- 休館日・休業日・休講日・休暇期間などに具体的な日付が記載されている場合、その日付または期間を除外します。
- 休みの記載だけで具体的な日付が分からない場合は、曜日や日付を推測して削除しません。
- 「休暇期間を除く」とだけ記載され、休暇の日付が示されていない定期開催は、回数表記だけで後半の日程を切り捨てません。明示された休止日だけを除外します。

### 日付抽出とイベント判定

- 「12月1日～5日」「12月1日から5日」など、終了側の月が省略された範囲表記にも対応します。
- 全角数字・和暦・ISO形式・通常の年月日表記を扱います。
- 「上旬」「下旬」「来年夏」など日付を確定できない表現は登録しません。
- 公開日・掲載日・更新日・申込期間を開催日として流用しません。
- 「このページに関するお問い合わせ」などのフッター見出しやカテゴリ案内ページをイベントとして登録しません。
- 日付抽出失敗と、イベントではないページを別の除外理由として診断します。

### 生成ファイルの整合性

- iCal、地図JSON、`source_status.json` に同じ `app_version`、`generated_at`、`execution_id` を記録します。
- iCalにも `X-EDOGAWA-EXECUTION-ID` と `X-EDOGAWA-GENERATED-AT` を記録します。
- 3ファイルを同じ実行で作成し、一時ファイルにすべて書き出してから置換します。
- GitHub Actionsでは3ファイルの実行ID・生成時刻・バージョンが一致することを確認してから、同じコミットで更新します。
- 取得失敗時は公開中のiCal/JSON/ステータスを更新せず、失敗診断を `source_status_failed.json` に分けます。

### 既存の品質条件を維持

- 江戸川区内の開催場所が確認できないイベントは除外します。
- 会場の住所または既知施設マスターから区内所在地を確認し、座標を確定できない場合は出力しません。
- 過去イベント、極端に遠い日付、カテゴリ・案内ページ、区外会場を除外します。
- 公式CSV、公式カレンダー、施設一覧、RSS/Atom、学校・スポーツ施設などの既存取得元を維持します。Kintone/KViewerは収集対象外です。

## GitHubリポジトリへの配置

ZIPを展開し、ZIP内のファイルをリポジトリのルートへ配置してください。親フォルダごと入れ子にしないでください。

```text
games/
├── edogawa_ical.py
├── edogawa_venues.json
├── geocoding_cache.json
├── requirements.txt
├── README_EDOGAWA_ICAL.md
├── tests/
│   ├── __init__.py
│   └── test_edogawa_ical.py
└── .github/
    └── workflows/
        └── update_ical.yml
```

既存のワークフローが `.github/workflows/update_ical.yml` 以外のファイル名の場合は、古いワークフローとの二重実行を避けるため、既存ファイルを置き換えてください。

### Gemini API設定

GitHubリポジトリ `Settings → Secrets and variables → Actions` に、次のRepository secretを登録してください。

- Name: `GEMINI_API_KEY`
- Value: Google AI Studioで発行したAPIキー

APIキーはソースコード、JSON、ログに出力しません。Geminiの無料枠を超過した場合はその月の球場抽出が失敗ステータスになり、別の有料モデルには切り替えません。無料枠の利用上限はGoogle側の変更・プロジェクト状態に依存します。

手動実行はGitHub Actionsの `Update Edogawa Events iCal` を選び、`Run workflow` を押してください。実際のGemini API呼び出しを含む動作確認は、キーを設定したGitHub Actions実行で確認してください。
