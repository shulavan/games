# 江戸川区イベント iCal v3.2.2

江戸川区内で実際に開催され、開催日・会場・区内所在地を確認できたイベントを収集し、iCalendar (`.ics`) と地図表示用 JSON を生成します。

## v3.2.2 の主な変更

### 開催日を1日ごとに分割

- 複数日開催は、開催日ごとに独立した VEVENT を生成します。例：12月1日～5日は5件です。
- 毎週・毎月第N曜日の開催は、各開催日を個別の VEVENT に展開します。
- 複数日・定期開催イベントは `PRIORITY:9`（iCalendarで最低優先度）を設定し、通常の単発イベントより目立ちにくくします。表示順への反映はカレンダーアプリの仕様に依存します。
- 開催日ごとのUIDを生成するため、同じイベントでも開催日が違えば別レコードとして扱います。

### 定休日・休館日

- 「月曜日は休館日」「定休日は月曜日」など、曜日が明記されている場合は該当曜日を除外します。
- 休館日・休業日・休講日・休暇期間などに具体的な日付が記載されている場合、その日付または期間を除外します。
- 休みの記載だけで具体的な日付が分からない場合は、曜日や日付を推測して削除しません。
- 「休暇期間を除く」とだけ記載され、休暇の日付が示されていない定期開催は、回数表記だけで後半の日程を切り捨てません。明示された休止日だけを除外します。

### 日付抽出とイベント判定

- 「12月1日～5日」「12月1日から5日」など、終了側の月が省略された範囲表記にも対応します。
- 全角数字・和暦・ISO形式・通常の年月日表記を扱います。
- 「上旬」「下旬」「来年夏」など日付を確定できない表現は登録しません。
- 公開日・掲載日・更新日・申込期間を開催日として流用しません。
- 「このページに関するお問い合わせ」などのフッター見出しやカテゴリ案内ページをイベントとして登録しません。
- 日付抽出失敗と、イベントではないページを別の除外理由として診断します。

### 生成ファイルの整合性

- iCal、地図JSON、`source_status.json` に同じ `app_version`、`generated_at`、`execution_id` を記録します。
- iCalにも `X-EDOGAWA-EXECUTION-ID` と `X-EDOGAWA-GENERATED-AT` を記録します。
- 3ファイルを同じ実行で作成し、一時ファイルにすべて書き出してから置換します。
- GitHub Actionsでは3ファイルの実行ID・生成時刻・バージョンが一致することを確認してから、同じコミットで更新します。
- 取得失敗時は公開中のiCal/JSON/ステータスを更新せず、失敗診断を `source_status_failed.json` に分けます。

### 既存の品質条件を維持

- 江戸川区内の開催場所が確認できないイベントは除外します。
- 会場の住所または既知施設マスターから区内所在地を確認し、座標を確定できない場合は出力しません。
- 過去イベント、極端に遠い日付、カテゴリ・案内ページ、区外会場を除外します。
- 公式CSV、公式カレンダー、施設一覧、RSS/Atom、学校・スポーツ施設、KViewer連携などの既存取得元を維持します。

## GitHubリポジトリへの配置

ZIPを展開し、ZIP内のファイルをリポジトリのルートへ配置してください。親フォルダごと入れ子にしないでください。

```text
games/
├── edogawa_ical.py
├── edogawa_venues.json
├── geocoding_cache.json
├── requirements.txt
├── README_EDOGAWA_ICAL.md
├── tests/
│   ├── __init__.py
│   └── test_edogawa_ical.py
└── .github/
    └── workflows/
        └── update_ical.yml
```

既存のワークフローが `.github/workflows/update_ical.yml` 以外のファイル名の場合は、古いワークフローとの二重実行を避けるため、既存ファイルを置き換えてください。

## GitHub Actions

- Python 3.12
- `requirements.txt` の依存関係をインストール
- 77件のユニットテスト
- 12か月分のイベント収集
- iCal・JSON・ステータスの生成整合性チェック
- 成功時は4つの公開データファイルを同じコミットで更新
- 毎日日本時間06:00に自動実行、`workflow_dispatch` で手動実行可能

KViewerの外部公開APIを使う場合は、GitHub Secrets に `KVIEWER_API_URL` を設定してください。未設定の場合は未設定として診断されます。

## ローカルテスト・実行

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -u edogawa_ical.py --months 12
```

## 注意事項

- カレンダーアプリによっては `PRIORITY:9` を表示順に反映しません。
- 公式情報に定休日・休館日の日付がない場合、推測で除外しません。
- 「休暇期間を除く」など休暇日の具体的な記載がない定期開催は、曜日に基づいて展開します。休止日が公式ページに追加された時点で、その日を除外できます。
- GitHub Actionsの実行結果と公開ファイルの更新を確認してから、v3.2.2の本番安定性を判断してください。ローカルテスト成功だけで取得元の網羅性まで保証するものではありません。
