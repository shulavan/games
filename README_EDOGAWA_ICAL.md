# 江戸川区イベント iCal v3.2.1

江戸川区内で開催される、今日以降に参加可能なイベントを収集し、iCalendar (`.ics`) と地図表示用 JSON を生成します。

## v3.2.1 の主な改善

- 記事の公開日・掲載日・更新日・一覧カードの`<time>`をイベント開催日として採用しません。詳細ページに開催日が明示されない場合は除外します。
- 「開催日時」「開催日」などの明示欄を優先し、ニュース形式でも「12月10日に開催します」のように開催意図と日付が同じ文中にある場合だけ日付候補として扱います。
- イベント日付が特定できない記事は採用しません。
- 昨日までに終了したイベントを除外します。昨日以前に始まり、今日以降も開催中のイベントは残します。
- 366日を超える異常な開催期間を除外します。開催日が今日から550日より先のデータも除外します。
- 「くらし・手続き」「よくある問い合わせQ&A」「サイトマップ」「スポーツ・文化」「健康・医療・福祉」「組織図と組織一覧」「フロア案内」「外国の方向け生活情報」「区内の主なイベント」など、案内・カテゴリページを除外します。
- 詳細ページの本文・会場・住所に「上野動物園」「恩賜上野動物園」などの区外施設名があれば除外します。施設運営者のニュースに別会場のイベントが掲載されるケースにも対応します。
- 詳細ページに会場が明記されている場合、取得元の既定会場より詳細ページの会場を優先します。
- 同一開催日・同一会場・類似タイトルのイベントを統合し、参照元URL・画像・座標・時刻・説明を補完します。
- 江戸川区外の会場を除外する既存の厳格な所在地チェックを維持します。
- 公式CSV、公式カレンダー、施設ページ、RSS/Atom、会場マスター、地図JSON、取得元診断を維持します。

## GitHub リポジトリへの配置

ZIPを展開し、**ZIP内のファイルをリポジトリのルートへ配置**してください。`edogawa_ical_v3_release/` という親フォルダごと入れ子にしないでください。

```text
games/
├── edogawa_ical.py
├── edogawa_venues.json
├── requirements.txt
├── README_EDOGAWA_ICAL.md
├── tests/
│   ├── __init__.py
│   └── test_edogawa_ical.py
└── .github/
    └── workflows/
        └── update_ical.yml
```

## GitHub Actions

`workflow_dispatch` で手動実行でき、毎日日本時間06:00にも実行します。

処理は次の順序です。

1. Python 3.12 をセットアップ
2. `requirements.txt` の依存関係をインストール
3. 49件のユニットテストを実行
4. 12か月分のイベントを収集
5. `edogawa_events.ics`、`edogawa_events.json`、`source_status.json`、更新された `edogawa_venues.json` を生成
6. 変更があればGitHubへコミット

## 出力ファイル

- `edogawa_events.ics`: カレンダー購読用
- `edogawa_events.json`: 地図・アプリ表示用
- `source_status.json`: 取得元ごとの成功件数、失敗、除外状況
- `edogawa_venues.json`: 会場名・住所・座標のマスター

## 注意点

- 開催日が記事本文から明確に確認できない場合は、誤った日付を付けず除外します。
- 会場が江戸川区内と確認できない場合は採用しません。
- 類似タイトルの重複統合は、開催日・会場・時刻も併せて判定し、別イベントを不用意に統合しないようにしています。
- 366日を超えるイベントは安全側に倒して除外します。長期展示などで本当に必要なものは、後から例外ルールを設けてください。
- 公開iCal URLはGitHubリポジトリの公開設定に従います。

## ローカルテスト

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

## ローカル実行

```bash
python edogawa_ical.py --months 12
```

KViewerの公開APIを使う場合は、GitHub Secrets に `KVIEWER_API_URL` を登録してください。未設定の場合は `not_configured` として扱います。


## v3.2.1 のバージョン確認

GitHub Actions の先頭で `edogawa_ical.py` の読み込み先と `APP_VERSION` を表示します。
`3.2.1` 以外の場合は、古いファイルが残っているためテスト前に停止します。
ZIP内のファイルはすべてリポジトリのルート基準で配置してください。

`source_status.json` にも `app_version: 3.2.1` が記録され、iCalの `PRODID` も `v3.2.1` になります。

区外施設名の除外は本文中の一致も対象にします。たとえば上野動物園を紹介する説明文を含むイベントも除外されるため、区内会場であっても本文に該当施設名が出てくるイベントは収録されません。


## v3.2.1 追加改善
- 江戸川区公式イベントCSVと東京都OpenDataの実際の列名に合わせて、開催日・住所・会場・詳細URL・画像・説明を正しく対応付けます。
- 座標が未登録の会場は国土地理院住所検索APIで補完し、施設名だけの場合はNominatimを低頻度で照会します。江戸川区内と確認できないイベント、座標を確定できないイベントは出力しません。
- 週次・月次の定期講座を、長期間の単一イベントではなく開催日ごとのVEVENTに展開します。
- 図書館・エコセンターのイベント一覧を取りこぼしにくいよう、候補リンク・会場文脈の抽出を強化します。
- KViewerの公開ページも診断対象に含め、API未設定と公開ビュー取得不可を区別します。
- 詳細ページ取得に成功したのに0件となった取得元は unexpected_zero として警告し、coverage_completeをfalseに保ちます。

- 住所欄の「ホームページ」等の付加文言を除去してジオコーディングし、区名だけの曖昧な代表点は会場座標として採用しません。
- CSVの列構成認識と、有効イベントを実際に取得できたことを別のヘルス指標として扱います。
- 江戸川区立図書館のTLSハンドシェイク失敗時は、同サイトに限定してTLS 1.2接続へフォールバックします。図書館イベントの個別タイトル・日時・館名を抽出します。
- 都立高校の詳細確認上限を各校50件から250件へ拡大し、候補の取りこぼしを減らします。
- 総合文化センターは、一覧カードに記載された開催日・会場を詳細ページの補助情報として利用し、タイトルは公演一覧のイベント名を優先します。
- KViewerは公開ビューURLだけでなく、管理画面で発行する外部公開API URL（GitHub Actions の `KVIEWER_API_URL`）を設定した場合にレコード取得します。
